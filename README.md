# Система кредитного скорингу

Це проєкт на **Spring Boot**, що надає **REST API** для прогнозування кредитоспроможності клієнта в режимі реального часу. В основі системи лежить модель машинного навчання, збудована за допомогою бібліотеки **Tribuo** та класифікатора **XGBoost**.

Проєкт демонструє повний цикл роботи з ML-моделлю: від аналізу та очищення даних до тренування, оптимізації та розгортання у вигляді готового до використання мікросервісу.

---

## 🚀 Як це працює: Від даних до прогнозу

Модель пройшла декілька етапів підготовки, щоб досягти максимальної точності та надійності.

### **Крок 1: Підготовка даних**

* **Джерело**: Модель навчалася на відкритому датасеті з Kaggle: [Lending Club Loan Data](https://www.kaggle.com/datasets/ethon0426/lending-club-20072020q1), який містить знеособлені дані про кредити, видані з 2007 по 2020 роки.
* **Очищення**: З великого масиву даних були відібрані лише ті поля, що найбільше впливають на фінальне рішення. Дані були очищені від помилок та пропусків.

### **Крок 2: Вирішення проблеми дисбалансу**

* **Проблема**: Початковий аналіз даних показав, що кількість виданих кредитів значно перевищувала кількість відмов. Навчання на таких даних призвело б до того, що модель була б схильна завжди давати позитивну відповідь.
* **Рішення**: Щоб навчити модель однаково добре розпізнавати обидва випадки, ми застосували **зважування класів**. Випадкам з відмовою у кредиті (яких було менше) була надана більша "вага" під час навчання. Це змусило алгоритм приділяти їм більше уваги.

### **Крок 3: Оптимізація та фінальне тренування**

* **Підбір параметрів**: Для подальшого покращення якості ми використали процес підбору найкращих гіперпараметрів для моделі. Оптимізація проводилася за **метрикою F1-score**, що є ідеальним показником для задач з незбалансованими класами.
* **Тренування**: Після знаходження оптимальних параметрів модель була фінально натренована на всьому підготовленому наборі даних.

### **Крок 4: Збереження моделі**

Готова, оптимізована модель була збережена у файл, який тепер використовується нашим REST API для надання швидких прогнозів.

---

## 📖 Використання API

Щоб отримати прогноз, потрібно надіслати `POST` запит на вказаний ендпоінт з JSON-об'єктом, що містить дані клієнта.

**Ендпоінт:** `POST /api/v1/credit-scores/predict`

### Поля для заповнення

Ось опис полів, які необхідно надіслати в тілі запиту.

| Поле (`JSON`)         | Назва                                | Опис                                                                                                         | Приклад заповнення     |
| --------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------ | ---------------------- |
| `loan_amnt`           | Сума кредиту                         | Повна сума, яку запитує клієнт.                                                                              | `10000.0`              |
| `term`                | Термін кредиту (в місяцях)           | Кількість місяців, на які видається кредит.                                                                  | `36`                   |
| `int_rate`            | Відсоткова ставка                    | Річна відсоткова ставка по кредиту.                                                                          | `11.44`                |
| `grade`               | Кредитний грейд                      | Внутрішній рейтинг позичальника, присвоєний кредитором (від A до G).                                          | `"B"`                  |
| `emp_length`          | Досвід роботи (в роках)              | Стаж роботи на поточному місці. `0` для менш ніж року, `10` для 10+ років.                                    | `10`                   |
| `home_ownership`      | Тип володіння житлом                 | Статус володіння житлом. Можливі значення: `RENT`, `OWN`, `MORTGAGE`.                                          | `"RENT"`               |
| `annual_inc`          | Річний дохід                         | Загальний річний дохід клієнта.                                                                              | `65000.0`              |
| `verification_status` | Статус верифікації доходу            | Чи був дохід перевірений кредитором. Можливі значення: `Verified`, `Not Verified`, `Source Verified`.           | `"Not Verified"`       |
| `purpose`             | Ціль кредиту                         | На що плануються витратити кошти. Наприклад: `credit_card`, `debt_consolidation`, `home_improvement`.         | `"credit_card"`        |
| `dti`                 | Співвідношення боргу до доходу (DTI) | Відсоток місячного доходу, що йде на сплату боргів.                                                          | `18.6`                 |
| `fico_range_low`      | Нижній поріг FICO                    | Нижній показник кредитного рейтингу FICO.                                                                    | `675`                  |
| `fico_range_high`     | Верхній поріг FICO                   | Верхній показник кредитного рейтингу FICO.                                                                   | `679`                  |
| `open_acc`            | Кількість відкритих кредитів         | Кількість відкритих кредитних ліній у клієнта.                                                               | `10`                   |
| `pub_rec`             | Публічні записи про банкрутство      | Кількість негативних публічних записів (напр. банкрутство).                                                  | `0`                    |
| `revol_bal`           | Баланс на кредитних картах           | Загальна сума боргу на всіх кредитних картах.                                                                | `15000.0`              |
| `revol_util`          | Використання кредитного ліміту (%)   | Відсоток використання доступного кредитного ліміту.                                                          | `55.9`                 |
| `total_acc`           | Загальна кількість кредитів          | Загальна кількість кредитних рахунків, які коли-небудь мав клієнт.                                           | `35`                   |
| `initial_list_status` | Статус лістингу                      | Початковий статус лістингу позики. Можливі значення: `w` (whole), `f` (fractional).                          | `"w"`                  |
| `application_type`    | Тип заявки                           | Тип поданої заявки. Можливі значення: `Individual` (індивідуальна), `Joint App` (спільна).                     | `"Individual"`         |

### Приклад запиту (Request Body)

```json
{
    "loan_amnt": 10000.0,
    "term": 36,
    "int_rate": 11.44,
    "grade": "B",
    "emp_length": 10,
    "home_ownership": "RENT",
    "annual_inc": 65000.0,
    "verification_status": "Not Verified",
    "purpose": "credit_card",
    "dti": 18.6,
    "fico_range_low": 675,
    "fico_range_high": 679,
    "open_acc": 10,
    "pub_rec": 0,
    "revol_bal": 15000.0,
    "revol_util": 55.9,
    "total_acc": 35,
    "initial_list_status": "w",
    "application_type": "Individual"
}
```

### Приклад відповіді (Response Body)

* **decision** — фінальний вердикт: APPROVED (схвалено) або REJECTED (відмовлено).
* **score**    — впевненість моделі у своєму рішенні (від 0.0 до 1.0).

```json
{
    "decision": "APPROVED",
    "score": 0.897
}
```
